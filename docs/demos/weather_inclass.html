Web scraping

Happily, someone has written a scraper:

git clone git@github.com:Karlheinzniebuhr/the-weather-scraper.git
cd the-weather-scraper
pip install lxml requests
# edit stations.txt and config.py
python weather_scraper.py

and then WAIT. (There’s 5-second timeouts between requests.)

Each station has it’s own file, so we concatante them. Also note the call to pd.to_datetime() to turn date + time into a datetime object.

def read_wf(f):
    x = pd.read_csv(f).convert_dtypes()
    x['code'] = f.split("/")[-1].split(".")[0]
    return x

    
wfiles = glob.glob("data/weather_2025/*.csv")

weather = pd.concat([read_wf(f) for f in wfiles])
weather['Date'] = pd.to_datetime(weather['Date'] + " " + weather['Time'], format="%Y/%m/%d %I:%M %p")

Goals:

What we’d like to do is understand how well rainfall in one part of Eugene/Springfield predicts rainfall in another part. In particular, how well does rainfall at one point – the National Weather Service station – predict load for the municipal stormwater system?

Precipitation

We’re interested in precipitation particularly, so let’s try to understand how “accumulated precip” relates to “precip rate”.

this_station = "KOREUGEN127"
this_weather = weather.query(f"code == '{this_station}' and Date > '2025-03-12' and Date < '2025-03-16'")

(
    this_weather
    >> p9.ggplot(p9.aes(x="Date", y="Precip_Accum_mm"))
    + p9.geom_line()
    + p9.labs(title=this_station + " accumulated precip")
) / (
    this_weather
    >> p9.ggplot(p9.aes(x="Date", y="Precip_Rate_mm"))
    + p9.geom_line() + p9.geom_point()
    + p9.labs(title=this_station + " precip rate")
)

Interesting: “accumulated precip” rises (until something gets full?) and then drops to zero - maybe at midnight?

It looks like - at least roughly - “accumulated precip” only goes up when “precip rate” is nonzero. This would make sense if “precipitation rate” is “how much rain accumulated since the last measurement” divided by “how much time since the last measurement”. Let’s see if that holds.

pd.crosstab(
    this_weather['Precip_Accum_mm'].diff() > 0,
    this_weather['Precip_Rate_mm'] > 0,
)
Precip_Rate_mm False True
Precip_Accum_mm
False 601 240
True 0 310

Short answer here is that it doesn’t hold. So, “rate” is estimated in some other way. Probably if we want to get “how much rain fell between time X and time Y” then we need to subtract “rain accumulated up to time X” from “rain accumulated up to time Y”, while dealing somehow with the “resets” (drops to zero).

Temperature and pressure

Let’s just look at some more things: for instance, how’s temperature and pressure change together? To see this reasonably we’ll zoom in on a few stations, in just one month.

Note: it’s important to use geom_path here, instead of geom_line, since the latter sorts points by position on the x-axis.

(
    weather
    .loc[weather['code'].isin(["KOREUGEN321", "KOREUGEN303", "KOREUGEN127"]) & (weather['Date'].dt.month == 3),:]
    >>
    p9.ggplot(p9.aes(x="Temperature_C", y="Pressure_hPa", color="Humidity_%"))
    + p9.geom_point(alpha=0.5, size=1, shape=".")
    + p9.geom_path(alpha=0.2)
    + p9.facet_wrap("code")
    + p9.theme(figure_size=(12,6))
)
